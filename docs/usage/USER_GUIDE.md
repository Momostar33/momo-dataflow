# Momo DataFlow 使用说明

版本：0.1.0-beta.1；修改日期：2026-11-27。基于StackRender二次开发，来源与许可证见仓库根NOTICE.md和LICENSE。

## 开始使用

按README运行 `npm ci`、`npm run dev`，打开 `http://127.0.0.1:4327`。点击“新建设计库”创建本地MySQL设计目录；或用顶部“导入设计包”导入[虚构示例](examples/design-package-v1.example.json)。不需要真实数据库账号。

导航只有表字段、类型模板、业务流程和只读关系总览。本版不保留原ERD窗口。

## 表、字段与流程

表支持技术名、说明名和备注。类型模板可供新字段继承，已有字段在模板发布后先预览再确认批量更新。金额模板固定两位小数，不将来源快照的原精度静默改成新目标。

为采购、收货等业务分别建流程，每个步骤拉入相关表。同一表定义一次，跨步骤用引用。多条件匹配支持ALL/ANY；直接映射和四则/括号公式只记录关系，不执行计算。不支持Excel函数。开始/结束/判断及条件/触发线用于绘图说明，不是任务执行器。

总览仅展示已保存关系；修改回到具体业务流程。字段隐藏只影响画布可见性，不是删字段。

## 保存与JSON

手动保存或默认每5分钟自动保存，可调整间隔。设计在当前浏览器个人资料、当前来源地址的本地SQLite；关闭服务前先保存。清除站点数据会删除设计。

可以直接编辑适配JSON，格式见[设计包v1](DESIGN_PACKAGE_JSON.md)。源文件与浏览器数据不会自动同步；在界面修改也不会自动回写文件。当前没有完整设计包导出闭环，不将Git当成浏览器数据备份。

导入v1只追加新库，不覆盖/合并。已有同名库或ID冲突会拒绝。修订后要重新导入时，先纳入用户修改，再生成新库名称及独立实体ID并重映射全部端点。只改packageId不足以避免冲突。

界面可以编辑的公式/判断/触发线，不代表包v1支持导入；v1只导入普通步骤分组、表引用和字段等值条件。完整公式和分支可先放备注供人工审阅。

## 用于需求确认

来源快照、现有实现、精简建议和用户明确确认分开。备注说明字段粒度、来源、单位/币种、完整关联键、异常和版本。先确定权威来源，再考虑移除重复字段；分配总额和尾差不能由舍入单价反推。

确认后将业务规则回写相应业务项目的spec/plan/tasks，工具文件不代替全部开发合同，也不自动授权模型编程或数据库迁移。缺失重要规则留在上游讨论。

## 常见问题

同名库/ID冲突：检查是否重复导入，修订另做新版本。改JSON页面没变化：文件不是实时存储。关系丢失：检查ref/table/field/flow端点及类型。原SQL类型未识别：类型说明会保留，不猜替代类型。保存失败：保留草稿、查看错误，不清空站点数据重试。
